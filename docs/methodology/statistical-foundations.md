# Statistical foundations (Milestone 3)

Status: `IMPLEMENTED`, `TESTED`, `SIMULATED` as of Milestone 3 — see
[../evidence/capability-status.md](../evidence/capability-status.md). Numerical evidence:
[../evidence/m3-statistical-foundations-results.md](../evidence/m3-statistical-foundations-results.md)
(generated by `python scripts/generate_m3_evidence.py`).

This document is the methodology of record for `src/decision_intelligence/statistics/` and the shared
primitives `common/bootstrap.py` and `common/validation.py`. For each method family it records the
twelve items required by Master Brief §17: question, estimand, data-generating assumptions,
modelling assumptions, formulation, implementation, baseline, evaluation, uncertainty, failure modes,
interpretation and decision relevance.

## Scope and boundaries

M3 delivers the statistical primitives every later pillar relies on. It deliberately does **not**
include causal identification or adjustment (M4), observational causal designs (M5), experimentation
infrastructure such as randomisation units, SRM checks or sequential monitoring (M6/M7), or Bayesian
decision analysis (M15). Where an M3 method is applied to M2 data, the only causal reading offered is
for the randomised experiment; every other group comparison or regression coefficient is reported as
an association.

## Cross-cutting conventions

| Concern | Convention |
| --- | --- |
| Invalid input | `common.validation` rejects NaN (unless explicitly allowed), infinities, wrong shapes, too-small samples and out-of-range probabilities with a `ValueError` naming the input. |
| Undefined quantities | Returned as NaN in descriptive summaries (e.g. variance of one value); **raised** wherever a test statistic or interval would otherwise be meaningless (constant data in a t-test, rank-deficient design, logistic separation). |
| Reproducibility | Every stochastic function takes an explicit `numpy.random.Generator`; nothing touches global random state. Evidence and tests use fixed seeds from `common.seeded_generator`. |
| Variance denominator | `n − 1` unless stated. |
| Quantiles | Linear interpolation (Hyndman–Fan type 7). |
| Confidence intervals | Two-sided at `confidence_level` for two-sided tests; for one-sided alternatives the matching one-sided bound, so test and interval agree. |
| Results | Tests return `HypothesisTestResult` carrying estimand, estimate, interval, assumptions and data-specific warnings, not just a p-value. |
| Dependencies | NumPy, pandas, SciPy (runtime: distribution functions, root-finding, special functions); statsmodels is a **test-only** reference oracle. |

## 1. Probability distributions and sampling — `statistics/distributions.py`

| Item | Content |
| --- | --- |
| Question | How do we generate draws from a specified distribution, and estimate a finite-population mean from a sample? |
| Estimand | (a) Draws with CDF `F`; (b) the finite-population mean `Ȳ = Σ_h W_h Ȳ_h`. |
| DGP assumptions | (a) A correct quantile function or density; (b) stratified simple random sampling without replacement. |
| Modelling assumptions | Rejection sampling requires the envelope `f(x) ≤ M g(x)` everywhere. |
| Formulation | Inverse transform `X = Q(U)`, `U ~ U(0,1)`. Accept–reject: accept `x ~ g` with probability `f(x)/(M g(x))`; acceptance rate `1/M`. Stratified estimator `ȳ_st = Σ W_h ȳ_h`, `Var = Σ W_h² (1 − n_h/N_h) s_h²/n_h`. |
| Implementation | Closed-form exponential/Weibull quantiles (the Weibull matches the M2 retention model); largest-remainder proportional allocation; exact KS distance at the empirical CDF's jump points. |
| Baseline | Simple random sampling for the stratified estimator; NumPy/SciPy reference distributions for samplers. |
| Evaluation | KS tests against SciPy distributions; Weibull draws reproduce the M2 property `P(T > 90) = p`; stratified estimator unbiased with < ¼ of the SRS standard deviation when strata explain variance; reported SE matches the empirical SD. |
| Uncertainty | Stratified SE with finite-population correction. |
| Failure modes | An invalid envelope **raises** (silent sampling from the wrong distribution is otherwise undetectable); exhausted proposal budget raises; strata receiving fewer than two units raise (variance inestimable). |
| Interpretation | `ks_distance` is a distance; no KS p-value is offered because estimated parameters invalidate it (Lilliefors). |
| Decision relevance | Stratification is how later pillars sample for evaluation or audit efficiently without biasing population estimates. |

## 2. Descriptive statistics — `statistics/descriptive.py`

| Item | Content |
| --- | --- |
| Question | What are the location, spread and shape of a variable? |
| Estimand | Population mean, variance, quantiles, skewness `γ₁`, excess kurtosis `γ₂`. |
| DGP assumptions | i.i.d. observations for the sampling-theory quantities (SEM); none for pure description. |
| Formulation | Two-pass moments; adjusted `G1 = √(n(n−1))/(n−2) · m₃/m₂^{3/2}`; bias-adjusted `G2`; MAD scaled by 1.4826 for normal consistency; trimmed mean cuts `⌊pn⌋` per tail. |
| Implementation | `RunningMoments` implements Welford's update with Chan et al.'s parallel merge for streaming/batched data. |
| Baseline | NumPy/SciPy (`stats.skew(bias=False)`, `kurtosis(bias=False)`, `trim_mean`, `median_abs_deviation`). |
| Evaluation | Agreement to floating-point precision with SciPy; with a 10⁹ offset the textbook `E[x²]−E[x]²` formula is shown to fail (> 1% error) while two-pass and Welford retain ~10⁻⁶ relative accuracy. |
| Uncertainty | `sem = s/√n`; intervals live in the inference modules. |
| Failure modes | Undefined summaries are NaN, not 0; NaNs are counted and dropped only when explicitly allowed. |
| Interpretation | `quantile_interval` describes data spread and must not be reported as a confidence interval. |
| Decision relevance | The mean/median gap on M2 revenue (23.9 vs 14.4) is the first indication that "average customer value" needs care before it drives budgets. |

## 3. Estimators, sampling distributions and the CLT — `statistics/estimators.py`

| Item | Content |
| --- | --- |
| Question | How good is an estimator, and when is normal-theory inference accurate? |
| Estimand | Bias, variance and MSE of `θ̂`; the distribution of `√n(x̄ − μ)/σ`. |
| DGP assumptions | A sampler that matches the population of interest; finite variance for CLT diagnostics (infinite σ is rejected). |
| Formulation | `MSE = bias² + Var`; CLT skewness of the mean `γ/√n`; exponential rate MLE `λ̂ = 1/x̄` with exact pivot `2λΣx ~ χ²_{2n}`; Student-t interval. |
| Implementation | `estimator_properties` reports the Monte Carlo SE of the bias, so "unbiased" is a statistical statement. |
| Baseline | Closed-form theory (`σ/√n`, `γ/√n`, `−σ²/n` bias of the ddof=0 variance). |
| Evaluation | ddof=0 variance bias matches `−σ²/n`; it has lower MSE than ddof=1 at n=10 (an estimator-level bias–variance trade-off); simulated SD of means matches `σ/√n`; skewness of means tracks `γ/√n` (evidence §9). |
| Uncertainty | Monte Carlo SEs reported for every simulated property. |
| Failure modes | The CLT says nothing about speed: log-normal(σ=1.5) t-intervals cover only 72% at n=10 and 88% at n=200 (evidence §7). Exponential MLE assumes uncensored data — censored durations need survival methods (M11). |
| Interpretation | "n ≥ 30" is not a universal rule; required n scales with population skewness. |
| Decision relevance | Determines whether a quick t-interval on a skewed business metric (revenue, basket size) can be trusted. |

## 4. Bootstrap confidence intervals — `common/bootstrap.py`

| Item | Content |
| --- | --- |
| Question | What is a confidence interval for a statistic without a convenient closed-form SE? |
| Estimand | Any smooth functional `T(F)` (mean, median, ratio, difference between groups). |
| DGP assumptions | i.i.d. observations within each sample; group sizes fixed (stratified two-sample resampling). |
| Modelling assumptions | `F_n` approximates `F` well enough — weak at small n. |
| Formulation | Percentile `[q_{α/2}, q_{1−α/2}]`; basic `[2T − q_{1−α/2}, 2T − q_{α/2}]`; BCa with `z₀ = Φ⁻¹(P*(T* < T) + ½P*(T* = T))` and jackknife acceleration `a = Σⱼ Σᵢ Uⱼᵢ³/nⱼ³ / (6 [Σⱼ Σᵢ Uⱼᵢ²/nⱼ²]^{3/2})`, `Uⱼᵢ = (nⱼ−1)(T̄₍.₎ⱼ − T₍ᵢ₎ⱼ)` with each sample centred on its own jackknife mean (reduces to Efron's `Σd³ / (6(Σd²)^{3/2})` for one sample). |
| Implementation | Single shared owner per the architecture's shared-utility rule. |
| Baseline | `scipy.stats.bootstrap` — identical intervals to ~10⁻¹⁰ for one sample with the same seed (identical resampling streams); within Monte Carlo error for two samples. The t interval is the parametric baseline. |
| Evaluation | Coverage study (evidence §7): exponential n=20, percentile 0.896, BCa 0.906, t 0.913 — the bootstrap does **not** beat the t interval at small n. On M2 revenue (n=2,000) t and BCa intervals for the mean nearly coincide. |
| Uncertainty | Bootstrap SE and bias are reported; bias is not subtracted from the estimate (that roughly doubles variance). |
| Failure modes | BCa raises when every replicate is on one side of the estimate; non-finite statistics on a resample raise; inconsistent for extremes (max); invalid for dependent data. |
| Interpretation | A resampling approximation to repeated-sampling behaviour, not a way to create information from small samples. |
| Decision relevance | Used for metrics without simple SEs (medians, ratios) in experimentation and decision science. |

## 5. Hypothesis testing — `statistics/hypothesis_tests.py`

| Item | Content |
| --- | --- |
| Question | Are the data compatible with a specific null hypothesis? |
| Estimand | Stated per test: difference in means (t), difference in proportions (z), Cramér's V (χ²), probability of superiority `P(X>Y)+½P(X=Y)` (Mann–Whitney), matched-pairs rank-biserial (Wilcoxon), η² (ANOVA), rank ε² (Kruskal–Wallis). |
| DGP assumptions | Independence within and between groups for every test; recorded in each result's `assumptions`. |
| Modelling assumptions | Parametric: approximately normal sample means (exact under normality), equal variances only for Student/ANOVA. Rank tests: exchangeability under H0; they test stochastic ordering, not means. Permutation: exchangeable labels. |
| Formulation | Welch–Satterthwaite df; pooled z with Newcombe hybrid-score interval; Pearson χ² without continuity correction; Mann–Whitney/Wilcoxon exact null distributions from Gaussian-binomial / `∏(1+qⁱ)` generating functions in **exact integer arithmetic**, otherwise normal approximations with tie-corrected variance; permutation p-values exact by enumeration when `C(n, n₁)` ≤ budget, else `(b+1)/(m+1)`. |
| Implementation | Welch is the default two-sample t; Fisher's exact and Shapiro–Wilk delegate to SciPy's validated implementations. |
| Baseline | SciPy `ttest_ind/1samp/rel`, `mannwhitneyu`, `wilcoxon`, `chi2_contingency`, `permutation_test`, `f_oneway`, `kruskal`, `levene`; statsmodels Wilson/Newcombe intervals — observed agreement ≤ 1e-12 (tests assert `pytest.approx`, default rel. 1e-6). |
| Evaluation | Type I error (evidence §6): Welch 0.052 under unequal variances where Student's pooled test reaches **0.256**; exact Mann–Whitney 0.046 (conservative, discrete); pooled z 0.050. Wilson coverage 0.950 vs Wald 0.870 at p=0.05, n=40. |
| Uncertainty | Intervals reported alongside every mean/proportion test. |
| Failure modes | Constant data, all-tied ranks, all-zero differences and all-zero table margins raise; sparse expected counts and ties produce warnings; z-test with no variation returns p=1 with a warning. Exact rank tests restricted to no ties and n ≤ 50 per group. |
| Interpretation | A p-value is not P(H0); `p > α` is not evidence of no effect; choose the test from the design before seeing the data (assumption-test-then-choose procedures distort error rates). |
| Decision relevance | M2 experiment: p = 0.109 with an interval of −0.7 to +6.9 points — "not significant" here means underpowered, not "no effect". |

## 6. Effect sizes — `statistics/effect_sizes.py`

| Item | Content |
| --- | --- |
| Question | How large is a difference, on a scale that supports a decision? |
| Estimand | Standardised difference δ (Cohen's d, Hedges' g, paired d_z); Cliff's δ; risk difference, risk ratio, odds ratio, Cohen's h. |
| DGP assumptions | As for the corresponding tests; noncentral-t intervals assume normality and (for d) equal variances. |
| Formulation | `g = J(df)·d`, `J = Γ(df/2)/(√(df/2)Γ((df−1)/2))` exactly; δ interval by inverting the noncentral-t CDF in its noncentrality parameter; Katz log RR and Woolf log OR intervals; Haldane–Anscombe +0.5 when any cell is zero (flagged). |
| Implementation | The noncentrality inversion is bracketed around the large-sample approximation `N(t, 1 + t²/2df)`; SciPy's `nct.cdf` returns NaN for some small-df, large-|t| inputs, so the CDF is evaluated through the exact identity `F(t; ν, δ) = S(−t; ν, −δ)` when the direct route fails; only if both fail is the normal approximation used, and **the result's note says so** (with an explicit caveat below 30 df, where that approximation is poor). No grid point tested (df 1–10,000, |t| ≤ 100) needs the fallback. |
| Baseline | statsmodels `Table2x2` (OR/RR and intervals); the defining property `F_nct(t_obs; ncp_L) = 0.975`; pairwise definition of Cliff's δ. |
| Evaluation | Exact agreement with references; graceful fallback verified at d≈10, n=4,000. |
| Failure modes | Zero pooled SD / constant differences raise. |
| Interpretation | Cohen's 0.2/0.5/0.8 labels are conventions, not decision thresholds; absolute risk differences drive expected value; odds ratios overstate risk ratios when outcomes are common. |
| Decision relevance | Risk difference × customers × margin is the quantity a later decision model (M15) consumes. |

## 7. Power, sample size and MDE — `statistics/power.py`

| Item | Content |
| --- | --- |
| Question | How large must a study be to detect the smallest decision-relevant effect? |
| Estimand | `P(reject H0 | δ)` for a specified δ; minimal n achieving target power; MDE at fixed n. |
| Modelling assumptions | Means: normal model, exact noncentral t (ncp `δ√(n₁n₂/(n₁+n₂))`). Proportions: normal approximation with pooled null SE and unpooled alternative SE. |
| Implementation | Integer sample-size search (exponential search + bisection) against exact power, so the returned design attains the target even with unequal allocation; refuses effects whose sign contradicts a one-sided alternative and designs needing > 10⁸ units. |
| Baseline | statsmodels `TTestIndPower`/`TTestPower` (agreement ≤ 1e-10), the closed-form proportion formula (n=3,841 per arm for 10% vs 12%), and the classic n=64 per group for d=0.5. |
| Evaluation | Analytic power vs simulated rejection rate of the implemented tests (evidence §8), e.g. d=0.5, n=64: 0.8015 analytic, 0.801 ± 0.006 simulated. |
| Failure modes | Normal approximation for proportions degrades with small expected counts. |
| Interpretation | **No post-hoc power**: effect sizes are design inputs, never the observed effect (observed power is a transformation of the p-value). |
| Decision relevance | The M2 experiment (≈566/arm) had ≈0.53 power for a 4-point lift; ≈1,080/arm were needed. |

## 8. Linear regression and robust inference — `statistics/linear_regression.py`

| Item | Content |
| --- | --- |
| Question | How does the conditional mean of an outcome vary with covariates, and how certain is that? |
| Estimand | Coefficients of the best linear predictor `E*[Y | X]`. Causal only with an identification argument (M4/M5). |
| DGP assumptions | Classical: independent, homoskedastic errors. HC0–HC3: independent, heteroskedastic. CR1: arbitrary correlation within clusters, independence between. |
| Formulation | QR-based OLS (never inverting X'X); sandwich `(X'X)⁻¹ X'ΩX (X'X)⁻¹`; HC2/HC3 leverage scaling; CR1 factor `G/(G−1)·(n−1)/(n−k)` with t(G−1) inference; Wald F for robust covariances. |
| Diagnostics | Internally studentised residuals, leverage, Cook's distance, Koenker–Breusch–Pagan, Jarque–Bera, Durbin–Watson (only meaningful for ordered data), VIF, condition number. |
| Baseline | statsmodels OLS/HC0–HC3/cluster SEs, `het_breuschpagan`, `OLSInfluence`, `variance_inflation_factor`, `durbin_watson`, `jarque_bera` — agreement ≤ 1e-8. |
| Evaluation | Dependence study (evidence §12): with intra-cluster correlation 0.8, classical **0.537** and HC3 **0.534** coverage vs cluster-robust **0.939**. On M2 transactions, customer-clustered SEs are 1.9–2.3× the classical ones. |
| Failure modes | Rank-deficient designs and n ≤ k raise (no pseudo-inverse); numerically zero residuals (exact fit, constant response) return NaN SEs/p-values with a warning rather than spurious certainty; the joint F-test is skipped with a warning when the covariance is singular (e.g. fewer clusters than slopes); HC2/HC3 with leverage-1 observations raise; < 30 clusters warns; condition number > 10⁸ warns. Breusch–Pagan only detects variance *linear* in the regressors — it misses e.g. variance in `|x|`. |
| Interpretation | Heteroskedasticity-robust SEs do not address dependence. |
| Decision relevance | Repeated measures per customer are the norm in this dataset; naive SEs would make weak associations look decisive. |

## 9. Logistic regression and classification diagnostics — `statistics/logistic_regression.py`

| Item | Content |
| --- | --- |
| Question | How does the probability of a binary outcome vary with covariates, and how good are predicted probabilities? |
| Estimand | Log-odds coefficients (conditional associations); predicted `P(Y=1|x)`. |
| Modelling assumptions | Independent Bernoulli outcomes; logit link linear in the regressors (the robust covariance remains valid for the pseudo-true parameter under link misspecification). |
| Formulation | Damped Newton–Raphson with step-halving on the log-likelihood (computed with `logaddexp` for stability); Wald inference from inverse Fisher information or HC0 sandwich; LR test vs the closed-form intercept-only likelihood; McFadden R². |
| Diagnostics | ROC AUC via the Mann–Whitney identity; Brier score; log loss; calibration-in-the-large; calibration slope (logistic recalibration on `logit p`); Hosmer–Lemeshow with documented caveats; quantile-binned calibration table. |
| Baseline | statsmodels `Logit` (coefficients/SEs ≤ 1e-8, HC0 ≤ 1e-7); on M2 retention, the base-rate predictor (training prevalence). |
| Evaluation | M2 retention, held-out customers (evidence §3): Brier 0.217 vs 0.241 baseline, log loss 0.621 vs 0.675, AUC 0.683. Calibrated vs over-confident probabilities are distinguished by slope (≈1 vs ≈⅓). |
| Failure modes | Complete and quasi-complete **separation raise `SeparationError`**, detected *exactly* before fitting: the MLE fails to exist iff some β ≠ 0 has `(2yᵢ−1)xᵢ'β ≥ 0` for all i (Albert & Anderson 1984), checked as a linear programme (Konis 2007) with SciPy's HiGHS. This matters because under quasi-separation Newton's method does not visibly fail — it "converges" with |η| ≈ 24 and SE ≈ 9×10⁴ — while a rule based on extreme fitted probabilities falsely rejects valid rare-event models. Non-binary or single-class outcomes and non-convergence raise. |
| Interpretation | Odds ratios ≠ risk ratios; AUC measures ranking, not calibration; in-sample calibration is optimistic, so diagnostics are computed on held-out data. |
| Decision relevance | Retention propensity feeds LTV (M10/M11) and targeting; whether its probabilities are calibrated determines whether they can be multiplied by margins. |

## 10. Bias–variance trade-off — `statistics/bias_variance.py`

| Item | Content |
| --- | --- |
| Question | How does model complexity trade bias against variance in prediction error? |
| Estimand | Integrated `E[(y − f̂(x₀))²] = σ² + bias² + variance` over a test grid. |
| DGP assumptions | Known `f` and `σ` (a simulation-study tool only). |
| Formulation | Fresh training sets per replication, **shared across models**; expected test MSE estimated directly from independent noisy test draws so the decomposition identity is a genuine check rather than a tautology. |
| Baseline | Low-degree polynomial; ridge at varying penalty as the continuous alternative. |
| Evaluation | Evidence §10: test MSE is U-shaped (degree 1: 0.160, degree 3: 0.101, degree 8: 0.486) while training MSE falls monotonically; simulated MSE matches the component sum within Monte Carlo error. |
| Failure modes / subtleties | Variance is **not** monotone in complexity under a random design (a misspecified line also varies with x-placement); high-degree fits extrapolate wildly at the domain edges, producing heavy-tailed variance. |
| Interpretation | Training error cannot choose complexity; held-out error must. |
| Decision relevance | The basis for model-selection discipline in recommenders (M8/M9), LTV (M11) and forecasting (M16). |

## 11. Missing data and selection bias — `statistics/missing_data.py`

| Item | Content |
| --- | --- |
| Question | When does analysing only observed values bias an estimate, and do simple fixes work? |
| Estimand | Full-data mean `E[Y]`. |
| DGP assumptions | MCAR / MAR (missingness depends on observed X) / MNAR (depends on Y itself); intercept solved so the expected missing rate is exact. |
| Modelling assumptions | Regression imputation assumes a correct linear model for `Y | X` among observed cases. |
| Strategies | Complete case; mean imputation; deterministic and stochastic regression imputation. |
| Baseline | Complete-case analysis. |
| Evaluation | Evidence §11 (n=200, 40% missing): MCAR complete case unbiased, coverage 0.942; MAR complete-case bias −0.256 (coverage 0.17), regression imputation bias ≈ 0 but coverage 0.80 (single imputation understates SE); MNAR biased for every strategy. On M2 income: M2's injected MCAR missingness leaves the complete-case mean within 0.3 SE of the full-data truth (a twin build without missingness); an imposed MAR mechanism biases it by ≈4.7 SE and regression imputation removes ≈73% of that bias. |
| Failure modes | MAR vs MNAR is untestable from observed data; single imputation (any kind) understates uncertainty. |
| Interpretation | Missing outcomes are a selection problem: the analysed sample is selected by a process related to the outcome. |
| Decision relevance | Income has injected missingness in M2; any segment-level income claim must state its missingness assumption. |
| Out of scope | Proper multiple imputation with Rubin's rules, IPW for missingness and sensitivity analysis for MNAR. |

## 12. Monte Carlo simulation — `statistics/simulation.py`

| Item | Content |
| --- | --- |
| Question | What is `E[g]` or a procedure's operating characteristic (type I error, power, coverage)? |
| Estimand | Expectations and rates over repeated sampling from a specified DGP. |
| Formulation | Sample mean of R draws, SE `s/√R`; rates with binomial SE. `SimulatedRate.is_consistent_with` uses the target's binomial SE, so it stays defined when the observed rate is 0 or 1. |
| Implementation | Explicit generators only; deterministic given a seed. |
| Evaluation | Used throughout this milestone's statistical-property tests (`tests/statistical/test_m3_statistical_properties.py`) with a 3.5-SE tolerance, so a correct procedure fails only through a code change. |
| Failure modes | Monte Carlo error is reported, but modelling error in the simulated DGP is not — simulated validation is not production validation. |
| Decision relevance | The engine behind design checks now and decision simulations in M15. |

## Leakage controls in the applied analyses

- `latent_value` (the generator's hidden driver) is never a feature; a test asserts it is absent.
- `dataset.ground_truth` is read only after estimation, to report recovery.
- Retention model: random split by customer; the baseline uses the *training* prevalence; all
  diagnostics are computed on held-out customers only.
- Post-outcome columns (`tenure_days`, `churned`) and the confounded campaign exposure are excluded
  from the retention features (asserted by a test).

## Known limitations

- Exact rank-test distributions are limited to untied data with ≤ 50 per group; larger or tied
  samples use normal approximations (tie-corrected).
- Power for proportions uses the normal approximation; exact (binomial) power is not implemented.
- No multiple-imputation, inverse-probability-weighting or MNAR sensitivity analysis (planned where
  M4/M5 and later pillars need them).
- No wild-cluster bootstrap; cluster-robust SEs warn below 30 clusters but do not correct.
- No multiple-testing corrections (family-wise / FDR) — required once experimentation analyses
  multiple metrics (M6).
- Penalised (Firth) logistic regression is not provided: separated data are rejected, not fitted.
- Data separated only up to the LP's numerical tolerance (~1e-7 per observation after column scaling) cannot be distinguished from exact separation.
- Logistic regression and OLS are dense-matrix implementations sized for this repository's bounded
  datasets (thousands of rows), not for very large data.
